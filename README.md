# DAMPER 재고관리

React + TypeScript + Vite 기반 반응형 프론트엔드입니다. React Router, CSS Modules, 공통 디자인 토큰, 로컬 Pretendard Variable, Lucide를 사용합니다. 서버 없이 전체 데모 흐름을 실행할 수 있습니다.

## 실행

Node.js 22 이상 권장. 검증 환경은 Node.js 24입니다.

```bash
cd client
npm install
npm run dev          # 기본 http://127.0.0.1:5173
npm run build        # TypeScript 검사 + 프로덕션 빌드
npm run preview
npm test             # 도메인·서비스 테스트
npx playwright install chromium
npm run test:browser # Chromium 통합 검증, 자체 로컬 서버 사용
npm run format
```

위 npm 명령은 `DAMPER/client`에서 실행합니다. 루트에서 실행하려면 `npm --prefix client run dev`처럼 `--prefix client`를 지정하세요. 기존 개발 서버가 켜져 있다면 종료 후 새 경로에서 다시 실행하세요.

## 저장소 구조

```text
DAMPER/
├─ .git/                  기존 GitHub 저장소
├─ .gitignore
├─ README.md
├─ client/                React 앱, npm 설정, 브라우저 검증
├─ design/                디자인·와이어프레임·엑셀 분석 결과
├─ scripts/               원본 엑셀 분석용 Python 스크립트
└─ DAMPER재고관리(최종).xlsx
```

향후 `server/`에 Spring Boot 프로젝트를 생성하고 IntelliJ에서 해당 폴더를 열면 됩니다. 현재는 클라이언트만 분리했으며, Git 저장소는 루트 하나를 그대로 사용합니다.

SPA 배포 시 `/inventory` 등의 경로를 `index.html`로 fallback하도록 웹 서버를 설정하세요.

의존성 보안 경고를 수정하여 Vitest는 4.1.11 이상, SheetJS는 0.20.3을 사용합니다. `xlsx`는 [SheetJS 공식 설치 안내](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/)에 따라 공식 CDN 패키지를 지정했습니다. `package-lock.json`도 함께 유지하며, 일반 `npm install`로 설치합니다.

## 계정과 권한

공통 데모 비밀번호는 `Damper123!`입니다.

| 계정 | 권한 |
| --- | --- |
| admin@damper.demo | 관리자: 재고·계획 편집, 승인·거절, 사용자 권한 변경 |
| editor@damper.demo | 편집: 자재·계산식·재고·계획 수정 |

| pending@damper.demo | 승인 대기: 회사 재고 접근 차단 |

역할 전환: **더보기 → 로그아웃** 후 다른 계정으로 로그인. PC에서는 사이드바 하단 사용자 이름으로 더보기에 접근합니다. 메뉴뿐 아니라 직접 URL 접근과 mock 저장 서비스에서도 권한을 검사합니다.

회원가입은 이름·이메일·비밀번호·확인·회사·회사 식별정보를 검증하고 승인 대기로 접수합니다. 데모 회사 식별정보는 `DAMPER-001`입니다. 관리자가 회사정보 확인 후 조회/편집 권한으로 승인할 수 있습니다. 다른 회사 식별정보는 승인하지 않습니다.

**가입 비밀번호는 검증 후 폐기합니다.** 새로 가입한 이메일로 재로그인할 때도 공통 데모 비밀번호를 사용합니다. 실제 비밀번호와 인증 토큰은 저장하지 않습니다. `sessionStorage`에는 인증 효력이 없는 데모 사용자 ID만 저장합니다.

## 원본 데이터와 확인 필요 사항

분석 대상은 `DAMPER재고관리(최종).xlsx`. 8개 날짜 시트와 빈 `Sheet1`, 최신 유효 시트 **2026.9.14**, **자재 282개 / 모델 40개**입니다. 원본은 수정하지 않았습니다. `design/legacy-*`는 다른 엑셀 기반 참고 자료여서 그 데이터와 계산 기준은 사용하지 않았습니다.

- `J43:J324` 현재재고를 **2026.09.14 종료 스냅샷**으로 보존합니다. 웹 거래는 2026.09.15부터 오늘까지 입력합니다. 과거 입고·사용·분실을 다시 차감하지 않습니다.
- 초기 계획은 원본의 **2026.10, 총 133대**입니다. 다른 월은 0부터 시작합니다.
- 모델 연결과 소요량은 `M43:M324` 계획 수식을 구문 분석해 추출했습니다. 추출 소요량으로 재계산한 282행 모두 원본 M열 저장값과 일치합니다. 전일재고+입고−사용−분실도 J열과 282행 모두 일치합니다.
- 빈 규격은 `미기재`, 단위는 `개`, ID는 원본 행번호 `R43` 등으로 표시합니다. 원본 음수 재고도 보존합니다.
- **15개 자재의 사용량(G열)과 계획(M열) 수식이 불일치합니다.** 정답을 임의 확정하지 않았습니다. 계획은 M열 기준 임시값으로 표시하고, 관련 모델의 조립 사용량 저장은 자재 편집에서 소요량을 검토·확정하기 전까지 차단합니다. 직접 사용 입력은 가능합니다.
- 원본 누계의 과거 시트 참조에도 불일치가 있어 누계와 달성률은 가져오지 않습니다.

불일치 셀·수식·모델별 차이: [EXCEL-REVIEW.md](design/EXCEL-REVIEW.md). 전체 시트 추출 결과: `design/workbook-analysis.json`. 앱 초기값: `client/src/data/seed.json`.

다음 Python 명령은 `DAMPER` 루트에서 실행합니다. `client`에 있다면 먼저 `cd ..`로 이동하세요. 출력 경로는 실행 위치와 무관하게 저장소 기준으로 결정됩니다.


## 계산·저장 규칙

1. 날짜별 현재재고 = 전일재고 + 입고 − 사용량 − 분실/파손/불용. 현재 총재고는 초기 스냅샷과 모든 날짜의 변동을 합산합니다. 과거 날짜 수정도 이후 재고에 반영됩니다.
2. 사용량은 선택일 **누적 합계 교체**입니다. 12 → 15 수정 시 추가 차감은 3개. 반복 저장으로 중복 차감되지 않습니다. 입고·분실도 선택일 누적 합계 교체입니다.
3. 직접 입력과 조립 계산은 선택 날짜 전체의 서로 배타적인 입력 출처입니다. 기존 사용량이 있으면 저장 전 전체 교체를 확인합니다. 조립수량은 모델별 누적값을 합산합니다. 혼용·가산 저장은 지원하지 않습니다.
4. 공용 자재는 한 재고를 공유합니다. 필요량 = Σ(모델별 계획 × 소요량). 모델 필터는 표시 대상만 바꾸고 공유 재고나 전체 계획 합산을 분리하지 않습니다.
5. 과부족 = 현재재고 − 필요량. 음수 절댓값이 부족수량입니다. 고정 안전재고 기준은 사용하지 않습니다.
6. 수식 변수는 `q`(조립/계획 수량), `rate`(모델별 소요량). 숫자와 `+ - * / ( )`만 지원합니다. `q * rate * 0.5` 같은 선형 수식만 허용하며 q=0일 때 결과도 0이어야 합니다. `q*q`, q로 나눗셈, 함수 호출, 속성 접근, JavaScript, 0으로 나눗셈은 차단합니다. `eval`/`Function`을 사용하지 않습니다.
7. 수량은 0~10억, 계산 결과는 0~1조 범위이며 조립·계획은 정수입니다. 변경한 BOM·수식은 향후 계산과 계획에 적용하고 이미 저장한 실적 사용량에는 소급하지 않습니다.
8. 조립가능대수는 현재재고 / 해당 모델의 실제 1대당 소요량으로 표시하는 **해당 자재 기준** 값입니다. 전체 BOM의 완제품 생산 가능 수량을 뜻하지 않습니다.

## 데이터 보존·데모 재현

`localStorage`의 `damper-demo-v1`에 재고·거래·계획·사용자 신청을 보존합니다. 기기 간 공유되지 않습니다. 관리자 **더보기 → 데모 환경 설정 → 데모 데이터 초기화**로 초기값을 복원합니다. 확인 후 해당 앱 키만 지웁니다.

편집 사용자/관리자의 **더보기 → 데모 환경 설정**:

- **동료 편집 중 표시**: 현재 편집 상태를 마지막 저장 이력과 구분합니다. 명시적인 데모 상태입니다.
- **다음 저장 실패**: 메뉴로 작업 화면에 이동해 저장하면 한 번 실패합니다. 입력을 유지하며 같은 버튼으로 재시도합니다.
- **외부 수정·충돌 재현**: 첫 자재의 기초재고를 1개 증가시키고 저장 버전을 올립니다. 메뉴로 이동해 저장하면 충돌 창이 열립니다. 최신 변경값 확인, 내 입력 JSON 다운로드, **최신 내용 반영 · 내 입력 유지** 후 재저장을 지원합니다. 새로고침하면 처음부터 최신 버전을 읽으므로 재현 시에는 메뉴로 이동하세요.

## 백엔드 연결 지점·한계

`client/src/services/api.ts`의 `load`, `login`, `register`, `save`를 Spring Boot API 구현으로 교체합니다. 화면은 `client/src/context.tsx`를 통해 연결되며 계산은 `client/src/domain`에서 공유합니다. 미연결 서버 주소를 호출하지 않습니다.

서버 구현에는 로그인/세션, 가입·회사 신청, 회사별 권한 검사, 자재/BOM/계산식, 날짜별 누적 거래, 월별 계획, 승인·권한, 알림 API가 필요합니다. 버전/ETag 기반 원자적 수정과 `409/412` 충돌 응답, 날짜·자재·입력 출처 기준 멱등 수정 및 트랜잭션, 동일한 수량·수식 검증을 서버에도 적용해야 합니다. 실제 편집 상태는 WebSocket/SSE 또는 임대·heartbeat 방식이 필요합니다.

현재 인증·권한은 **프론트엔드 데모**이며 실제 보안 경계가 아닙니다. 브라우저 데이터는 사용자가 변경할 수 있습니다. 기기 간 공유, 실제 인증, 실시간 다중 사용자 편집, 이메일·외부 푸시는 구현하지 않았습니다. 수식 불일치 15개는 업무 담당자의 확정이 필요합니다.
