# DAMPER 재고관리 — 공통 디자인 명세

> 버전: 1.0 · 기준: 최신 뉴트럴 PC·모바일 시안
> 이 문서는 밝은 사이드바, 얇은 구분선, 인디고 강조색을 사용하는 최신 시안을 구현하기 위한 기준이다. 이미지에서 측정한 값이 아니라, 시안의 방향을 일관되게 구현하도록 **새롭게 정의한 수치**다. 이전 네이비 사이드바·큰 카드 중심 시안과 혼용하지 않는다.

## 1. 디자인 방향

- 현장에서 휴대폰으로 입력하고, 사무실에서 PC로 여러 자재를 확인하는 반응형 웹사이트.
- 흰색·회색 기반의 차분한 업무용 화면. 강조색은 주요 버튼, 선택된 탭, 포커스에 제한한다.
- 데이터는 표와 목록으로 정리한다. 장식용 카드, 그라데이션, 큰 그림자, 과도한 배지, 불필요한 대시보드 차트는 사용하지 않는다.
- 시안 이미지에 남은 그라데이션·문자 오류·임의 수량보다 본 문서의 토큰과 실제 데이터가 우선한다.
- 핵심 정보는 이름·규격·재고·부족 여부다. 색상만으로 상태를 전달하지 않는다.
- 밝은 테마를 기본 범위로 한다. 다크 모드는 별도 설계 전까지 추가하지 않는다.

### 참고한 디자인 패턴

- [Atlassian Dynamic table](https://atlassian.design/components/dynamic-table/examples): 데이터 중심 표, 정렬·페이지 이동, 차분한 선택 상태.
- [shadcn/ui Dashboard](https://ui.shadcn.com/examples/dashboard): 중립적인 화면 구조, 사이드바와 툴바, 일관된 폼 구성.
- 특정 서비스의 화면을 복제하거나 위 라이브러리 도입을 강제하지 않는다. 아래 값은 DAMPER 전용 기준이다.

## 2. 폰트와 타이포그래피

기본 폰트는 **Pretendard Variable**이다. 정적 폰트를 사용한다면 400·500·600·700만 준비한다. 배포 프로젝트에서 라이선스를 확인하고 폰트 파일을 포함하며, 로딩 실패 시 시스템 폰트로 대체한다.

```css
font-family: "Pretendard Variable", "Pretendard", -apple-system,
  BlinkMacSystemFont, "Segoe UI", "Noto Sans KR", sans-serif;
```

| 용도 | PC 크기 / 행간 | 모바일 크기 / 행간 | 두께 |
| --- | --- | --- | --- |
| 페이지 제목 | 24 / 32px | 22 / 30px | 600 |
| 섹션·모달 제목 | 18 / 26px | 18 / 26px | 600 |
| 본문 | 14 / 22px | 14 / 22px | 400 |
| 표·목록 | 14 / 20px | 14 / 22px | 400 |
| 필드 라벨·버튼 | 14 / 20px | 14 / 20px | 500 |
| 입력값 | 14 / 20px | 16 / 24px | 400 |
| 보조 설명·수정 시각 | 12 / 18px | 12 / 18px | 400 |
| 주요 재고 숫자 | 20 / 28px | 20 / 28px | 600 |
| DAMPER 워드마크 | 18 / 24px | 16 / 24px | 700 |

- 기본 자간 0. 제목에만 -0.02em까지 허용한다.
- 한국어 설명은 `word-break: keep-all; overflow-wrap: anywhere`로 처리한다.
- 수량은 `font-variant-numeric: tabular-nums`를 적용하고 오른쪽 정렬한다.
- 입력값을 제외한 표시는 천 단위 쉼표를 사용한다. 단위는 보조 텍스트로 구분한다.
- 모바일 입력값은 16px 이상으로 유지한다. 화면을 맞추기 위해 글자를 축소하지 않는다.
- 조립가능대수는 화면에서 최대 소수점 2자리로 표시하되 저장·계산 정밀도는 유지한다. 반드시 ‘해당 자재 기준’을 함께 표시한다.

- 얇은 장식용 구분선과 조작에 필요한 입력 경계를 구분한다. 입력 경계는 대비를 확보한다.

## 4. 간격·모서리·그림자

기본 간격은 4px 단위다.

| 값 | 대표 용도 |
| --- | --- |
| 4px | 아이콘·배지 내부의 작은 간격 |
| 8px | 아이콘과 글자, 라벨과 입력창 |
| 12px | 툴바 요소 간격, 표 셀 가로 여백 |
| 16px | 모바일 화면 여백, 필드 사이 |
| 24px | PC 섹션 간격, 모바일 주요 섹션 간격 |
| 32px | PC 화면 내부 여백, 큰 섹션 사이 |
| 48px | 로그인 폼 상단 등 제한된 큰 여백 |

- 입력창·버튼 모서리: 6px.
- 메뉴 선택 배경: 6px. 표 외곽: 6px 또는 무테.
- 모달: 12px. 모바일 바텀시트: 상단 모서리만 16px.
- 배지: 4px. 아바타·상태 점만 원형. 일반 버튼에 알약 모양을 쓰지 않는다.
- 화면·표·폼의 기본 그림자는 없다.
- 드롭다운: `0 4px 12px rgb(15 23 42 / 10%)`.
- 모달: `0 16px 48px rgb(15 23 42 / 16%)`.

## 5. 반응형 레이아웃

| 구간 | 범위 | 구조 |
| --- | --- | --- |
| 모바일 | 0–767px | 단일 열, 하단 메뉴, 목록형 재고 |
| 태블릿 | 768–1199px | 1–2열, 메뉴 버튼으로 여는 내비게이션, 상세는 drawer |
| PC | 1200px 이상 | 고정 폭 사이드바, 표 중심 본문 |

### PC

- 사이드바 224px, 상단 헤더 56px, 본문 padding 32px.
- 화면 전체에 고정 폭을 주지 않는다. 본문은 남은 가로 폭을 채운다.
- 재고표는 최대 폭 제한 없이 확장한다. 일반 폼은 720px, 로그인 폼은 360px를 기준으로 한다.
- 상세 패널은 320px. 표와 함께 표시할 공간이 부족하면 오른쪽 drawer로 전환한다.
- 툴바는 제목 → 주요 액션 → 검색·필터 → 표 순서. 공간이 부족하면 줄바꿈한다.
- 사이드바 하단에는 사용자·회사 정보를 배치한다. 주메뉴는 4개로 고정한다.

### 태블릿

- 본문 padding 24px, 상단 헤더 56px.
- 사이드바는 숨기고 메뉴 버튼으로 연다. 아이콘만 남겨 의미를 추측하게 하지 않는다.
- 편집표의 열이 많으면 표 영역 안에서 가로 스크롤한다. 페이지 전체는 넘치지 않는다.

### 모바일

- 본문 좌우 padding 16px, 상단 헤더 최소 52px.
- 하단 메뉴 높이 56px + 기기 안전영역. 메뉴는 `사용 입력 / 재고 / 계획 / 더보기`.
- 하단 고정 저장 영역이 있다면 본문에 그 높이만큼 padding을 추가해 마지막 필드가 가려지지 않게 한다.
- 하단 메뉴와 고정 저장 버튼은 서로 겹치지 않는다. 중첩 상세·편집 화면에는 하단 메뉴를 숨긴다.
- 재고표는 목록으로 바꾸고 자재명·규격·현재재고·부족 여부를 우선 노출한다.
- 필터·내보내기는 바텀시트, 자재·계산식처럼 긴 입력은 전체 화면 모달로 전환한다.
- 화면이 좁아지면 2열 입력을 1열로 바꾼다. 숫자 키패드가 열려도 현재 필드와 저장 동작에 접근할 수 있어야 한다.
- 확인 폭: 360 / 390 / 430 / 768 / 1024 / 1280 / 1440px. 320px에서도 페이지 가로 넘침은 없어야 한다.

## 6. 공통 컴포넌트

### 6.1 버튼

| 종류 | 높이 | 좌우 padding | 스타일 |
| --- | --- | --- | --- |
| PC 기본 | 36px | 14px | 14px/500 |
| PC 표 내부 | 32px | 10px | 12px/500 |
| 모바일 기본 | 44px | 16px | 14px/500 |
| 모바일 하단 저장 | 48px | 16px | 전체 폭 |
| 아이콘 버튼 | PC 36px / 모바일 44px | 정사각형 | 접근 가능한 이름 필수 |

- Primary: 인디고 단색, 흰 글자. 한 작업 영역에는 원칙적으로 한 개.
- Secondary: 흰 배경, control-border, 기본 글자색.
- Ghost: 배경 없음, hover 시 회색. 행 메뉴·부가 작업에 사용.
- Destructive: 거절·삭제처럼 결과를 되돌리기 어려운 작업에만 사용.
- 저장 중: spinner + ‘저장 중…’, 중복 실행 방지. 실패하면 입력값을 그대로 유지한다.
- 미저장 변경이 없거나 폼이 유효하지 않으면 저장 버튼 비활성. 이유는 필요한 경우 설명한다.

### 6.2 입력창·셀렉트

- 높이 PC 36px / 모바일 44px, 좌우 padding 12px, 테두리 1px.
- 라벨은 입력 위에 두고 8px 간격. PC에서 짧은 설정 폼만 좌우 라벨 배치를 허용한다.
- placeholder는 예시일 뿐 라벨을 대체하지 않는다.
- 수량은 오른쪽 정렬. 단위 ‘개 / 대’는 필드 옆에 고정한다.
- 정수 수량은 `inputmode="numeric"`, 소수 수량을 허용하는 자재는 `inputmode="decimal"`을 사용한다.
- 읽기 전용 값은 기본적으로 일반 텍스트. 자동 계산값을 수정 가능한 입력처럼 보이게 하지 않는다.
- 오류는 빨간 경계 + 필드 아래 12px 문구. 예: ‘0 이상의 수량을 입력하세요.’
- focus-visible: primary 2px outline, offset 2px. 기존 포커스 스타일을 제거하지 않는다.
- 체크박스 18px, 상태 스위치 36×20px. 모바일 클릭 영역은 최소 44×44px.
- 날짜 `YYYY.MM.DD`, 계획월 `YYYY.MM`. 입력값과 날짜 표시의 형식을 구분한다.

### 6.3 데이터 테이블

- 헤더 40px, 기본 행 최소 48px, 편집 입력이 있는 행 최소 52px.
- 셀 padding 12px, 세로 구분선은 기본 생략, 가로 1px border.
- 헤더는 surface-subtle, 12px/500. 데이터 14px, 숫자 오른쪽·텍스트 왼쪽 정렬.
- 줄무늬 대신 hover 배경을 사용한다. 선택 행은 옅은 배경으로 표시한다.
- 현재 편집 중인 행은 왼쪽 2px 인디고 표시와 ‘김민수 편집 중’을 함께 표시한다.
- 수정자는 ‘이지은 · 14:20’ 형식으로 작게 표시. 실제 수정 이력으로 연결할 경우 별도 상세 UI에서 제공한다.
- 자재명 최소 160px, 규격 96px, 수량 96px, 수정자 140px, 행 메뉴 40px 기준.
- 상세·사용 빈도가 낮은 작업은 행 끝 `…`에 둔다. 모든 행에 진한 액션 버튼을 반복하지 않는다.
- 헤더 정렬 아이콘은 정렬 가능한 열에만 사용한다. 페이지 이동·페이지당 행 수는 표 아래 배치한다.
- 전체 목록의 정보: 자재명, 재질, 수량/1대, 적용모델, 규격, 전일재고, 투입수량, 분실/파손/불용, 입고, 현재재고, 조립가능대수, 알람, 투입계획, 과부족.
- 기본 표에는 핵심 열만 보여주고 나머지는 상세 패널에서 제공한다. 숨긴 정보를 삭제하지 않는다.

### 6.4 모바일 목록

- 항목당 padding 16px 0, 최소 높이 88px. 배경은 흰색, 항목 사이 구분선.
- 첫 줄: 자재명·규격 / 현재재고. 둘째 줄: 재질·적용모델 / 계획 필요량·부족수량.
- 셋째 줄은 동시편집·수정 시각이 있을 때만 사용한다.
- 행 전체로 상세에 접근할 수 있으나 내부 별도 버튼과 클릭 영역이 충돌하지 않게 한다.
- 부족 배지는 작은 텍스트 중심으로 처리한다. 커다란 빨간 박스를 반복하지 않는다.

### 6.5 메뉴·탭·아이콘

- 사이드바 항목 높이 40px, 좌우 padding 12px, 항목 간격 4px.
- 탭 높이 40px, 탭 간격 24px. 활성 탭은 인디고 글자와 2px 밑줄.
- 모바일 탭 클릭 높이는 44px 이상. `SCR-LP`와 `ICER`를 각각 독립된 탭으로 구현한다.
- 아이콘은 한 종류의 선형 아이콘 세트로 통일한다. 구현 선택은 Lucide 계열, 선 두께 1.75px 기준.
- 툴바 아이콘 16px, 내비게이션 20px, 모바일 하단 메뉴 20px.
- 의미가 불명확한 아이콘 단독 사용을 피한다. 아이콘 전용 버튼에는 aria-label과 PC tooltip을 둔다.

### 6.6 팝업·상세 패널

| 유형 | PC | 모바일 |

| 자재 추가·계산식 편집 | 폭 720px 모달 | 전체 화면 모달 |
| 간단 확인 | 폭 400px 대화상자 | 화면 폭−32px |
| 필터 | 폭 320px popover 또는 drawer | 바텀시트 |
| 자재 상세 | 폭 320px 패널 또는 420px drawer | 별도 상세 화면 |
| 엑셀 내보내기 | 폭 400px 대화상자 | 바텀시트 |
| 알림 | 폭 360px popover | 알림 전체 화면 |

- 모달 최대 높이 `calc(100dvh - 48px)`, 내부 본문만 스크롤. 헤더·액션은 접근 가능하게 유지한다.
- 바텀시트 최대 높이 90dvh, 상단 handle 32×4px, 하단 safe-area 반영.
- 모달 열기 시 포커스를 이동·가두고 닫으면 원래 버튼으로 복귀한다.
- 미저장 변경이 있으면 닫기 전 ‘수정 내용을 버릴까요?’를 확인한다. 배경 클릭으로 입력을 잃지 않게 한다.

## 7. 화면별 적용 규칙

| 화면 | 주요 구성 | 주 액션 |
| --- | --- | --- |
| 금일 사용 입력 | 날짜 → 직접 입력/조립수량 탭 → 수량 → 반영 후 재고 | 사용수량 저장 또는 조립실적 저장 |
| 재고관리 | 검색·필터 → 목록·표 → 상세 | 자재 추가, 편집 상태의 저장 |
| 생산계획 | 계획월 → 제품군 탭 → 모델별 계획 → 필요 자재 | 계획 저장 |
| 권한 관리 | 승인 요청/사용자 관리 탭 → 회사정보·권한 | 승인, 권한 변경 |
| 로그인 | 이메일·비밀번호 → 로그인 → 가입 링크 | 로그인 |
| 회원가입 | 이름·계정정보·회사정보 → 제출 | 가입·권한 신청 |
| 더보기 | 사용자·회사·권한 → 관리·내보내기·로그아웃 | 선택한 메뉴로 이동 |

- 모바일 시작화면은 금일 사용 입력. PC에서도 동일한 메뉴 순서를 유지한다.
- 첫 로그인 후 승인 대기 사용자는 대기 상태를 보여주고 회사 재고를 노출하지 않는다.
- 로그인과 가입은 별도 화면이다. 생성 이미지의 ‘신청 후 상태’는 설명용 예시이며 실제 가입 폼 아래에 상시 표시하지 않는다.
- 엑셀 내보내기는 ‘현재 필터 결과 / 전체 자재’를 선택하고 파일명을 확인한다.
- 권한 관리는 관리자에게 표시한다. 조회 권한에는 편집 버튼을 숨기거나 필요한 경우 읽기 전용 이유를 명시한다. 서버에서도 권한을 검사해야 한다.
- PC 사용자 관리 탭과 승인 요청 탭은 실제로 다른 내용을 표시한다. 시안처럼 두 내용을 항상 한 화면에 중복 노출하지 않는다.

## 8. 계산·동시편집이 UI에 미치는 규칙

### 수량·계산식

- 현재재고 = 전일재고 + 입고수량 − 사용수량 − 분실/파손/불용.
- 필요 자재량 = Σ(모델별 생산계획 × 해당 모델의 자재 소요량).
- 과부족 = 현재재고 − 필요 자재량. 음수이면 부족 알림을 표시한다.
- ‘제품 계획 10대’와 ‘자재 8개’를 직접 비교하지 않는다.
- 공용 자재는 모델별 필요량을 합산한다. 모델 필터를 바꿔도 공용 재고 자체가 나뉘지 않는다.
- 오늘 사용 입력은 선택 날짜의 **누적 합계 수정**이다. 기존 사용량이 12개인데 15개로 고치면 추가 차감은 3개다.
- 반영 후 재고는 원래 기초값과 입력 전체로 재계산한다. 이미 차감된 현재재고에서 누적량을 다시 빼지 않는다.
- 직접 사용 입력과 조립수량 자동 계산은 동일 사용량을 이중 차감하지 않도록 출처와 전환 규칙을 확정해야 한다. 이 문서는 계산 엔진 명세를 대신하지 않는다.
- 자재별 모델·소요량 편집을 기본으로 제공한다. 사용자 정의 계산식은 검증 결과·미리보기를 보여주고 유효한 경우에만 저장한다. 임의 코드 실행 기능으로 만들지 않는다.
- 원본 엑셀에서 발견한 공용 자재 소요량 차이·이전 날짜 누계 참조 문제는 별도 검증 후 확정한다. 이미지의 예시 숫자는 업무 정답으로 사용하지 않는다.

### 동시편집

- ‘편집 중’은 현재 상태, ‘마지막 수정자’는 저장된 이력으로 구분한다.
- 이름·시각은 서버 상태로 표시한다. 초기 화면에 고정된 예시 이름을 남기지 않는다.
- 다른 사용자의 변경이 저장되어 충돌하면 자동 덮어쓰지 않는다.
- 충돌 안내: ‘다른 사용자가 이 항목을 수정했습니다.’ + `최신 내용 확인` + `내 입력 복사` 등 복구 가능한 동작.
- 사용자 입력을 유지한 채 변경된 필드를 비교하게 한다. 행 전체를 붉게 칠하지 않는다.

## 9. 공통 상태와 접근성

| 상태 | 표현 |
| --- | --- |
| 초기 로딩 | 표·목록 구조와 맞는 중립 skeleton |
| 빈 목록 | ‘등록된 자재가 없습니다’ + 권한이 있으면 자재 추가 |
| 검색 결과 없음 | ‘조건에 맞는 자재가 없습니다’ + 필터 초기화 |
| 저장 성공 | 작은 toast ‘저장했습니다’ 약 3초, 레이아웃 이동 없음 |
| 저장 실패 | 입력 유지 + 인라인 오류 + 재시도 |
| 입력 오류 | 필드 아래 구체적 원인, 첫 오류 필드로 이동 |
| 승인 대기 | 작은 황색 상태와 대기 설명 |
| 읽기 전용 | 자동 계산값과 권한 제한을 구분해 안내 |
| 네트워크 끊김 | 상단 작은 배너, 저장 완료로 표시하지 않음 |

- 본문 텍스트 대비 4.5:1 이상, 큰 글자 3:1 이상을 목표로 실제 조합을 확인한다.
- 조작에 필요한 경계·포커스는 인접 배경 대비 3:1 이상을 확인한다.
- 모바일 터치 영역 최소 44×44px. 시각적 아이콘 크기와 클릭 영역을 구분한다.
- label·aria-describedby·aria-invalid·aria-current 등 의미에 맞는 속성을 사용한다.
- 표는 실제 table, 헤더는 th, 정렬 상태는 aria-sort로 전달한다.
- 키보드만으로 메뉴·표 액션·폼·모달 저장까지 접근할 수 있어야 한다.
- 오류·저장 결과는 적절한 live region으로 전달하며, 실시간 편집 이벤트를 과도하게 읽어주지 않는다.
- 색상만으로 성공·부족·편집 상태를 구분하지 않는다.

## 10. 움직임·레이어

- hover·색상 전환 120ms, 메뉴·모달 전환 180ms, easing `cubic-bezier(0.2, 0, 0, 1)`.
- 버튼 확대, 반복 pulse, 로딩 시 큰 등장 애니메이션은 사용하지 않는다.
- `prefers-reduced-motion: reduce`에서는 이동 애니메이션을 제거한다.
- 레이어: 본문 0 / sticky header 20 / 하단 메뉴·저장 바 30 / dropdown 50 / overlay 100 / modal 110 / toast 120.
- 모달 내부 dropdown은 해당 모달보다 위에 표시되도록 portal 계층을 관리한다.

## 12. 공통 컴포넌트 구조 제안

```text
AppShell / DesktopSidebar / MobileBottomNav / PageHeader
Button / IconButton / TextField / NumberField / Select / DatePicker
Tabs / Checkbox / Switch / StatusLabel / UserAvatar
InventoryTable / InventoryListItem / MaterialDetail
FilterBar / FilterSheet / Pagination / PresenceIndicator
```

- 도메인 계산과 표시 컴포넌트를 분리한다. 화면 크기에 따라 표·목록만 바꾸고 계산 로직을 복제하지 않는다.
- 버튼·필드·모달은 한 번 정의한 공통 컴포넌트를 사용한다.
- 기능 구현 스택과 무관한 명세이며 React + TypeScript에 적용할 수 있다.

## 13. 구현 완료 확인

- [ ] 최신 뉴트럴 시안의 폰트·색상·간격을 모든 화면에서 일관되게 사용한다.
- [ ] PC 4개 메뉴와 모바일 업무·계정·관리 화면의 기능이 누락되지 않는다.
- [ ] 모바일에서 데이터 표를 억지로 축소하지 않고 목록·상세로 재구성한다.
- [ ] 직접 입력과 자동 계산값, 저장 전과 저장 후 상태가 명확하다.
- [ ] 같은 날 수량 수정과 직접/자동 입력 전환으로 중복 차감되지 않는다.
- [ ] 공용 자재·부족 알림·계산식은 검증된 실제 데이터를 사용한다.
- [ ] 필터·내보내기·권한·동시편집 표시가 실제 상태와 연결된다.
- [ ] 오류·빈 상태·로딩·권한 제한·충돌 상태도 구현한다.
- [ ] 320–1440px 범위에서 겹침·잘림·가려지는 저장 버튼이 없다.
- [ ] 키보드·포커스·대비·모바일 터치 영역을 확인한다.
- [ ] 이미지의 오탈자, 임의 데이터, 그라데이션을 그대로 복사하지 않는다.
