# DAMPER 재고관리 MVP

`재고관리시트xlsx.xlsx`의 실제 자재·재고·생산 수식을 분석해 만든 React + TypeScript 웹앱입니다. 원본 엑셀은 수정하지 않으며, 웹에서 발생한 변경은 브라우저 `localStorage`의 `damper-inventory-mvp-v1` 키에 저장됩니다.

## 실행 방법

Node.js 18 이상이 필요합니다.

```bash
npm install
npm run dev
```

터미널에 표시되는 주소(기본 `http://localhost:5173`)를 브라우저에서 엽니다.

```bash
npm test       # 엑셀 수식 변환 검증
npm run build  # TypeScript 검사 및 배포 빌드
npm run preview
```

## 엑셀 분석 결과

분석 대상 실제 파일명은 요청에 적힌 `재고관리시트.xlsx`와 달리 `재고관리시트xlsx.xlsx`입니다.

### 시트와 구조

| 시트 | 용도 | 범위 | 특징 |
|---|---|---|---|
| `2026.9.3` | 9월 3일 생산·입고·재고 일보 | `A2:L122` | 최초 재고 데이터 |
| `2026.9.4` | 9월 4일 생산·입고·재고 일보 | `A2:L122` | F열이 전 시트 J열 참조 |
| `2026.9.5` | 9월 5일 생산·입고·재고 일보 | `A2:L122` | 웹 초기 데이터 기준 |

- 제품 생산량 입력: SCR-LP 제품은 `H3:H14`, ICER 제품은 `J3:J6`
- 자재표: 16행 헤더, 17~122행 데이터(총 106개 자재 행)
- 열: A 자재명, B 재질, C 기준 소요수량, D 적용제품, E 자재규격, F 전일재고, G 생산 투입수량, H 분실/파손, I 입고수량, J 현재재고, K 생산 가능 대수, L 알람
- 제품: SCR-LP 12종, ICER 4종(총 16종)
- 병합 셀: 모든 시트 `A7:E11`
- 숨김 시트·행·열: 없음
- 정의된 이름: 각 시트 자동 필터 범위 `A16:J122`와 깨진 `_xlnm._FilterDatabase = #REF!` 2개
- L열 알람 값/수식, 자재 코드, 제품 코드, 단위, 별도 분류, 최소·안전재고, 목표재고, 발주량 수식은 원본에 없음

자재 106개 전체의 원본 값은 `src/data/excelData.ts`에 행 번호와 함께 들어 있습니다. 같은 이름이라도 재질·규격·적용제품이 다르면 별도 자재로 유지했습니다. 제품은 SCR 400A, 450A, 500A, N500A, 550A, N550A, 600A, N600A, 650A, 700A, 750A, 800A와 ICER 600A, 700A, 800A, 1000A입니다.

## 변환한 주요 계산식

| 엑셀 | TypeScript 계산 |
|---|---|
| `G행 = 제품 생산량 × 자재 소요량` | BOM 항목 수량 × 입력 생산 수량 |
| `SUM(H3:H10)*C행` 등 공용 제품 범위 | 범위 안 각 제품에 해당 자재 BOM 연결 |
| `J행 = F행 + I행 - G행 - H행` | 현재고 + 입고 - 생산투입/일반출고/분실 |
| `K행 = J행 / C행` | 자재별 가능 대수(원본 표시값 보존) |
| 제품 최대 생산량 | `floor(min(각 BOM 자재 현재고 / 1대 소요량))` |
| 생산 후 잔량 | `현재고 - 총 필요량` |

G113~G120의 BOLT 수식은 C열 수량과 다른 개별 계수를 사용하므로 수식을 그대로 옮겼습니다. 예를 들어 G113은 SCR 400A~N600A에 16개, SCR 650A~750A에 12개이며, G118은 SCR 800A와 ICER 1000A에 각각 8개입니다.

## 구현 화면과 기능

- 대시보드: 자재 종류, 총재고, 오늘 생산 투입, 부족 자재, 최근 생산/입출고, 부족 알림, 구매 필요 목록
- 자재 관리: 106개 전 행, 검색, 상태 필터, 현재고·오늘 사용량·신청 상태
- 제품 및 BOM: 16개 제품별 실제 BOM, 생산수량별 필요량·잔량·생산 가능 여부
- 생산 등록: 미리보기, 부족 자재와 부족량, 최대 생산량, 부족 시 등록 차단, 확인 후 재고 차감
- 입고·출고: 입고/일반 출고/분실·파손 구분, 초과 출고 차단, 날짜와 비고 기록
- 부족 알림: 실제 BOM으로 계산한 생산 가능 수량이 10대 이하일 때 표시하며, 11대 확보에 필요한 수량을 권장 신청량으로 계산
- 수량 수정: 자재 목록에서 현재고 직접 보정, 기존/수정 수량과 차이 미리보기, 수정 사유 및 재고 조정 이력 저장
- 구매 신청: 중복 진행 신청 차단, 신청자·사유·상태 관리와 취소
- PC 사이드바, 모바일 슬라이드 메뉴, 표 가로 스크롤과 반응형 카드

## 임시 처리 및 확인 필요 사항

1. **최신 시트의 전일재고 참조:** `2026.9.5!F17:F122`가 예상되는 `2026.9.4!J17:J122`가 아니라 `2026.9.3!J17:J122`를 참조합니다. 임의 수정하지 않고 최신 시트의 저장된 J열 결과를 초기 현재고로 사용했습니다.
2. **깨진 이름 범위:** 통합 문서에 `#REF!`인 숨김 자동 필터 이름이 2개 있습니다. 재고 계산에는 쓰이지 않습니다.
3. **최소/안전/목표재고 없음:** L열도 전부 비어 있습니다. 사용자 지정 운영 기준에 따라 `floor(현재고 / 실제 BOM 1대 소요량) <= 10`을 부족 기준으로 사용합니다. 공용 자재는 연결 제품 중 가장 큰 소요량을 사용합니다.
4. **권장 구매량:** 알림을 벗어나는 11대분을 목표로 `11대분 자재 - 현재고 - 진행 중 신청량`을 계산합니다. 담당자가 신청 모달에서 수량을 수정할 수 있습니다.
5. **코드/단위/분류 없음:** 코드 대신 추적 가능한 원본 행(`R17` 등)과 제품 셀(`H3` 등)을 내부 코드로 표시합니다. 단위는 표의 개수 성격에 따라 `개`로 표시하며, 분류는 원본 B열 재질을 사용합니다.
6. **원본 음수:** `2026.9.5!J27`은 `0 + 0 - 0 - 1 = -1`입니다. 원본 결과를 보존하되, 웹에서 새 출고/생산이 재고를 더 음수로 만들지는 못하게 막았습니다.
7. **표기 오탈자 가능성:** 원본 `D119`는 다른 ICER 표기와 달리 `ICR 800A`입니다. 수식 `J5*C119`에 따라 BOM은 ICER 800A에 연결했고 원문 표기는 자재 목록에 유지했습니다.

## 코드 구조

- `src/data/`: 엑셀에서 추출한 초기 데이터와 BOM
- `src/types/`: 도메인 타입
- `src/services/`: 저장소, 재고 변경, 알림 판단
- `src/utils/`: 계산 함수와 엑셀 비교 테스트
- `src/App.tsx`: 페이지 구성과 사용자 흐름
- `scripts/analyze-workbook.ps1`: 원본을 변경하지 않는 OOXML 분석 도구

Spring Boot 연동 시 `inventoryRepository`를 API 구현으로 교체하고 현재 계산/화면 코드는 그대로 유지할 수 있습니다.

## 사용자가 신규 기준정보를 등록하는 방법

### 신규 자재

1. 왼쪽 메뉴에서 `자재 관리`를 엽니다.
2. 우측 상단 `＋ 신규 자재 등록`을 누릅니다.
3. 자재 코드, 자재명, 재질, 규격, 분류, 단위, 초기 재고를 입력합니다.
4. 등록된 자재는 아직 제품에 연결되지 않았으므로 `BOM 미연결`로 표시됩니다.
5. `제품 및 BOM`에서 기존 제품의 `BOM 편집`을 누르거나 신규 제품 등록 시 해당 자재를 연결합니다.

자재 코드는 대소문자와 관계없이 중복 등록할 수 없으며, 초기 재고는 0 이상이어야 합니다. BOM 미연결 자재는 생산 가능 수량을 산정할 수 없으므로 부족 알림 대상에서 제외됩니다.

### 신규 제품과 BOM

1. 왼쪽 메뉴에서 `제품 및 BOM`을 엽니다.
2. 제품 목록 상단 `＋ 제품 등록`을 누릅니다.
3. 제품 코드, 제품명, 제품군을 입력합니다.
4. `＋ 자재 추가`로 자재를 선택하고 제품 1대당 소요량을 입력합니다.
5. `제품과 BOM 등록`을 누르면 제품과 BOM이 함께 저장됩니다.

제품 코드 중복, 빈 BOM, 동일 자재 중복, 0 이하 소요량은 저장할 수 없습니다. 기존 제품은 `BOM 편집`에서 자재를 추가·삭제하거나 소요량을 바꿀 수 있습니다. BOM을 수정해도 이미 완료된 생산 이력의 실제 차감 수량은 유지됩니다.

제품과 BOM도 자재·입출고·생산·구매 신청과 함께 `localStorage`에 저장됩니다. 이전 버전에서 저장한 데이터에는 제품/BOM 필드가 없으므로 최초 실행 시 엑셀 기준 제품/BOM을 자동으로 보충하고 기존 재고와 이력은 보존합니다.
